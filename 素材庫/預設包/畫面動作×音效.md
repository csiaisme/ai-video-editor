# 畫面動作 × 音效 — 哪個畫面配哪個聲音

> 給 AI 選音效時讀的。用法:先看畫面上**真的有動**的是什麼(轉場、字卡、圈、zoom、定格…),在主表找那一列,拿「配什麼音效」那欄的檔案。**音量看 `對照表.md`**(每個檔的 volume 起點、LUFS),這份只管「配什麼、什麼時候響」。總量照 SKILL / 對照表:一支 3-6 個音效,每個都落在看得到的動作上,兩行字幕跟轉場自動帶的也算在內(`sfx_cues.py list` 看總數)。路徑都相對 `素材庫/預設包/音效/`,「缺」= 庫裡沒有合適的檔。來源代號見第 5 節;沒有來源、是我自己推的,標 [推論]。整理日期 2026-10-07。

## 1. 主表

### 1a. 剪接與轉場(transitions.py 9 個配方)

| 畫面動作 | 配什麼音效 | 備註 | 來源 |
|---|---|---|---|
| 一般剪點 / jump cut(剪掉停頓、NG) | **不配** | 大部分剪點不配,只有真的換場、揭曉、能量轉換才配。有來源主張每個 jump cut 都配 swipe,本 kit 不採用(見第 3 節衝突) | [S1] [S5] [K1] |
| push-slide(推入,進 b-roll / 字卡) | `3-轉場/woosh-1` | 檔長 0.42s、峰值 0.13s,跟 0.5s 動作長度吻合 | [K2] [S2] |
| whip(甩鏡) | `3-轉場/woosh-2` | 快甩配短促 whoosh;檔 1.5s,峰值 0.36s,尾巴可剪 | [K2] [S1] |
| iris-circle(圓形展開,常用在回程) | `3-轉場/woop` | | [K2] |
| shutter(快門,換段落最安全) | `3-轉場/camera-shutter` | 峰值 0.09s,幾乎貼齊畫面變化 | [K2] |
| glitch(故障,b-roll 回程 / 科技題) | `2-介面科技/glitch` | 只適合科技、數位話題,正經情感片不要用 [推論] | [K2] |
| blur-ripple(模糊漣漪,柔的轉場) | 預設 `3-轉場/deep-woosh`;**建議改不配,或剪短到 ≤0.6s 壓低音量** [推論] | 柔轉場來源建議「swell 或不配」;deep-woosh 3.25s 遠長於 0.4s 動作,違反長度對齊 | [K2] [S1] [S2] |
| card-flip(翻卡,進字卡) | `3-轉場/paper-slide` | 翻頁類轉場配翻頁/紙聲,是常見配法 | [K2] [S5] |
| color-blocks(色塊遮蓋,換段落) | `3-轉場/woosh-1` | | [K2] |
| blinds(百葉窗,換段落) | `3-轉場/paper-slide` | 來源配的是捲簾聲(rolling window),庫裡缺,paper-slide 先頂 | [K2] [S5] |

轉場一個配方 = 進 + 回兩個音效,一支 2-3 個轉場就吃掉大半額度 [K4]。

|---|---|---|---|
| 兩行字幕 `stamp` 蓋章 | `4-電影感/hit`(只放前 0.6s) | 剪短用要降音量,見對照表 hit 那列 | [K3] [K1] |
| 兩行字幕 `slide` 側滑 | `3-轉場/woosh-1` | | [K3] |
| 兩行字幕 `drop` 掉落 | `3-轉場/woop` | | [K3] |
| 兩行字幕 `type` 逐字 | `2-介面科技/keyboard-typing` | 原檔很小聲 | [K3] [K1] |
| 兩行字幕 `pop` 彈出 | `6-卡通復古/pop` | 檔頭有 0.22s 空白,gen_captions 已提早放 | [K3] |
| 螢光筆(關鍵字刷黃) | `3-轉場/camera-focus` | 嗶在檔案 0.78s,gen_captions 自動對齊;15 秒內不重複 | [K3] [K4] [K1] |
| 手繪紅圈(圈重點) | `5-真實動作/marker-circle` | 約 0.6s,對齊圈畫出來那 0.45s | [K1] [K4] |
| 手繪底線 / 手寫字出現 | `5-真實動作/pen-writing` | 檔約 1.1s,底線動畫 0.45s → 剪短到跟筆畫一樣長 [推論] | [K1] [S2] |
| 整框翻色(字幕框瞬間變黃) | 預設不配;要配用 `6-卡通復古/pop` | 這類小強調一支 2-4 個,全配會超額 [推論] | [K4] |
| 字卡 / 列點 / 文字彈出 | `6-卡通復古/pop`;科技題用 `2-介面科技/ping` | 來源:文字彈出配「小而圓、幾乎沒尾巴」的 pop | [S3] [K1] |
| 對話框逐字打出(7b) | `2-介面科技/keyboard-typing` | 長度跟打字動畫一致 | [K1] [推論] |
| 下方字條 / 卡片滑入(lower-third、人縮成卡片) | `3-轉場/paper-slide` 或 `3-轉場/woosh-1`,壓低 | 小元素用小聲音,長度對齊滑入時間 | [S2] [推論] |
| 重點重擊(slam,大字一個個砸) | `4-電影感/hit` 或 `boom`,**整組只配一下** | 不要每個字都砸一聲 [推論] | [K1] |
| 開場字卡轟炸(stomp) | `4-電影感/impact-bass-1` 落在第一張 | 很大聲,照對照表音量 | [K1] [推論] |

### 1c. 運鏡、特效、疊加層

| 畫面動作 | 配什麼音效 | 備註 | 來源 |
|---|---|---|---|
| punch-in zoom(推近強調) | `3-轉場/woosh-1` 或 `3-轉場/camera-shutter` | snap zoom 配起音快、收得快的 whoosh | [K1] [S1] |
| zoom-out / punch-out(拉回) | **缺**(下降音高的 whoosh);暫用 `3-轉場/woosh-2` 小聲,或不配 | 來源:重量感靠低頻 + 音高往下掉 | [S2] [推論] |
| step-zoom 揭曉(瞬放緩回) | 前鋪 `4-電影感/metallic-rise` → 落 `4-電影感/boom` / `hit` | | [K1] |
| 縮框 / 梗 / 吐槽 | `1-迷因梗/vine-boom`、`4-電影感/boom`、`6-卡通復古/womp-womp` | 彩蛋類一支最多 1-2 個 | [K1] |
| 畫面震動 screen shake | `4-電影感/impact-bass-1` 或 `boom`,跟震動第一格同時 | 來源:重要畫面配低沉、起音硬、尾巴短的 boom | [S3] [推論] |
| 閃光 flash(editorial-flash-overlay) | `3-轉場/camera-shutter` | 拍照時刻配快門聲;閃光燈充電聲缺 | [S4] [K1] |
| 定格・正經(freeze-frame-dressing,拍照感) | `3-轉場/camera-shutter` | | [K1] [S4] |
| 定格・搞笑(「等一下…」、反轉前一拍) | `1-迷因梗/record-scratch` | 刮停那下落在定格第一格 | [K1] [S4] |
| 漏光 / 回憶(organic-light-leak-overlay) | **不配**;要配就 `4-電影感/remembering-woosh` 很小聲 | 柔的畫面不配 whoosh,改用音樂音量變化 | [S1] [推論] |
| 通知跳出(macos-notification) | `2-介面科技/notification-sound`;柔一點用 `2-介面科技/chime` | 彈出 / 訊息配通知「叮」 | [S4] [S3] |
| IG 追蹤 CTA(instagram-follow,結尾) | 按下去 `2-介面科技/mouse-click`;要再加「叮」就 `2-介面科技/ping` | 來源:訂閱 CTA 配明亮單音「叮」,要能壓在人聲底下 | [S3] [推論] |
| 攝影機 REC 介面(camcorder-hud) | `2-介面科技/digital-beep` 在 REC 亮起那格 | 錄影機開機 / 磁帶聲缺 | [推論] |
| 揭曉 reveal(大反轉、公布答案) | `4-電影感/riser`(10s,最高點在檔尾,放在揭曉 −10s)→ `4-電影感/impact-bass-1` / `-2` / `boom` | riser 頂點要剛好落在揭曉那格,接重擊;頂點後的一瞬安靜更有力 | [S6] [S2] [K1] |
| 數字 / 數據跳出 | `2-介面科技/ping`;數字跑動用 `2-介面科技/glitchy-counter` | 遊戲風用 `7-遊戲/coin-collect` | [K1] |
| 講錯 / 錯誤 / 打叉 | 正經:`2-介面科技/error`;搞笑:`6-卡通復古/womp-womp`、`1-迷因梗/roblox-oof` | 來源:錯誤用短、平的 buzz,不要刺耳的遊戲節目蜂鳴 | [S3] [K1] |
| 清單打勾 / 達成 | `2-介面科技/chime`、`7-遊戲/level-up`、`7-遊戲/coin-collect` | | [K1] |
| 產品 / 重點物件發光出現 | `4-電影感/sparkle` | 來源:小成就用短的上升 sparkle,比掌聲小 | [S3] [K1] |
| b-roll 裡的具體動作(倒水、刷東西) | `5-真實動作/` 對應擬音 | 擬音貼著畫面動作 | [K1] [S4] |
| 結尾(收尾字卡、段落完成) | `2-介面科技/chime`(柔)或 `7-遊戲/level-complete`(遊戲風);或不配,只讓 BGM 淡出 | finalize.sh 已內建 BGM 淡出 | [K1] [推論] |

## 2. 選類速查

| 影片調性 | 主要用哪幾類 |
|---|---|
| 正經教學 / 專業 | 3-轉場、2-介面科技、4-電影感;少用梗 |
| 輕鬆搞笑 / 年輕向 | 1-迷因梗、6-卡通復古、7-遊戲 |

## 3. 時間與混音規則

| # | 規則 | 怎麼做 | 來源 | 衝突 / 備註 |
|---|---|---|---|---|
| 1 | 峰值落在新畫面第一格 | 音效從「畫面變化時間 − 檔案峰值秒數」開始放。transitions.py 跟 gen_captions 已自動算 | [S2] [K2] | riser 是例外的同一個道理:頂點落在切點,之後靜音 [S2] |
| 2 | 大部分剪點不配 | 只配真的換場、揭曉、能量轉換 | [S1] [S5] [K1] | **衝突**:[S3] 說每個 jump cut 都配 swipe。kit 不採用,口播一分鐘幾十刀,全配會變機械感 [K4] |
| 3 | 柔的轉場不配 whoosh | 溶接 / 漏光 / 模糊:不配,或只做音樂音量變化 | [S1] | blur-ripple 預設配 deep-woosh,跟這條衝突,建議改 [推論] |
| 4 | 音效出現時 BGM 壓低 3-6 dB,快速回復 | 音效那一下底下的 BGM 降 3-6 dB | [S1] | `sfx_cues.py mix` 有沒有自動做這步,我沒驗證 [推論] |
| 5 | 同一個音效 15 秒內不重複 | `sfx_cues.py list` 會警告 | [K5] | 來源同方向:同一聲 whoosh 用在每刀,很快就沒意義 [S1] |
| 6 | whoosh 長度 = 動作長度 | 動作 0.5s 就用約 0.5s 的 whoosh,長的剪短 | [S2] [S1] | 短切用短 whoosh,長的移動用長 whoosh [S2] |
| 7 | 音效比人聲低 11-14 dB | 量 ebur128 LUFS,不要用 volumedetect mean | [K1] | 來源:克制比大聲更專業,小音量播一次,聽不到才加 [S1] |
| 8 | 重擊放在沒講話的格子,尾巴要短 | 口播幾乎一直在講 → 放在換氣 / 句首開口前那一下 [推論] | [S3] | hit 只放前 0.6s 就是在砍尾巴 [K1] |
| 9 | riser 頂點對準揭曉 | 頂點後接 impact / sub-drop | [S6] | |
| 10 | 音效放自己的音軌 | 不要混進音樂軌 | [S1] | kit 的 sfx_cues.json 已經是獨立一軌 |

## 4. 還缺的音效(依優先順序)

| 優先 | 缺什麼 | 用在哪 | 現在先頂 |
|---|---|---|---|
| 高 | 下降音高的 whoosh(whoosh-down) | zoom-out、punch-out、卡片收走、人從卡片放回全螢幕 | `woosh-2` 小聲,或不配 |
| 高 | 短的柔和 swell(0.5-1s) | 柔轉場、漏光、blur-ripple | 不配(現有 deep-woosh / remembering-woosh 都 3s 以上) |
| 中 | 尾巴短的 sub-drop / 低音重擊 | 震動、標題落下,又不想吃掉人聲 | `hit` 剪短、`impact-bass` 壓低 |
| 低 | 捲簾聲 | blinds 轉場 | `paper-slide` |
| 低 | 閃光燈(閃光 + 充電聲) | editorial flash | `camera-shutter` |
| 低 | 錄影機開機 / 磁帶聲 | camcorder-hud | `digital-beep` |

優先順序是我依「kit 現有特效多常用到」排的 [推論]。補檔後記得在對照表加音量。
